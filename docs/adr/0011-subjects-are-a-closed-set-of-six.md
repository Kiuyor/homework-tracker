# 科目收为六个主科的闭集，取消自由输入自动建科

ADR-0004 放开科目输入的理由是「政治、历史、地理类作业无处可录」。真实库给出的答案是：**从来没有人录过**。`subjects` 表除六主科外 0 行，42 条作业全部落在语数英理化生上。开放集合这一能力被使用后一次也没有，而它的代价一直在付：一个能逐字敲的输入框、一套 `INSERT OR IGNORE` 幂等建科、一个候选框重画链路、一条「敲到已有科目就换成编辑态」的 49 行换算机制（含 `confirm` 弹窗与 focus 快照回滚），以及「第 13 个科目会与第 1 个撞色」这个永远悬着的待办。现决定六个主科就是科目全集，本 ADR 推翻 ADR-0004 的核心决定（科目是开放集合、自由输入自动建科）；其「列数固定、行数自适应」那半篇**继续有效**，因为下面第 6 条保留了表外科目上墙的路径，网格仍可能多于六格。

六条决定一并生效：

1. **名单升格**：`db.js:144` 的 `SUBJECT_PRIORITY` 从「排序依据 + 启动补齐清单」升为「科目全集」。名单仍只在这一处写一次——`api/index.js:22` 只 `require` 不复制，这条纪律是 ADR-0006 立的，继续有效。
2. **控件换形**：弹窗里的自由输入框 + `<datalist>` 换成六个按钮的分段选择器（复用 `.seg`）。按钮按当天状态显示哪几科已录。
3. **后端拒收，schema 不动**：`resolveSubject()` 的 `subject_name` 分支不再 `INSERT`，名字不在六科内返回 400。`subjects` 表、`GET /api/subjects`、启动时补齐六行都保留——与 `completed`/`note`/`sort_order` 同一条口径：留着不再写的列，不做不可逆的表变更。
4. **约束钉在录入侧，不钉在渲染侧**：墙上格子继续以 `GET /api/subjects` 的返回为准，`ui.js` 的分组代码零改动。若在前端再写死一份六科名单，就把第 1 条的纪律破了；而"渲染侧只认表里有的"意味着手改数据或旧备份回滚带来的第七行会在表尾正常显示，而不是让那条作业从墙上消失——"作业存在却看不见"是本项目最难排查的一类 bug，不引入。
5. **点到已录科目 = 直接改那一条**：不弹确认（按钮本身已说出这格不是空的，再问一次是多余）。连带删除 `snapshotSubjectInput`、`_subjectValueAtFocus`、`convertToAddModalEdit`、`state.subjectConvertedId` 整条链——它们的存在理由是"框可以逐字敲出中间态"（`ui.js:319-320` 那段注释就是在解释 `change` 与 `input` 之争），分段按钮没有中间态。ADR-0005 的入口语义不变，只是触发方式从"敲完名字"变成"点按钮"。**一个例外**：新建框里已经写了正文时不劫走这次点击，只把目标换成该科（保存时由 409 那句话指路）。规格故事 15 要"已输入的正文不许丢"，本条要"不弹确认"——不切换正好两条都守，代价是多一次取消。
6. **表尾 `ELSE` 档保留**：`priorityOrderSql()` 对表外科目的兜底不删，服务于第 4 条。因此"六科之外还能不能再有科目"的答案是：**不能新建，但历史数据仍会上墙**。

**取舍**：备选「钉在渲染侧，格子永远只有六格」被否决——它要前端复制名单，且会让表外科目的作业静默消失；备选「钉在渲染侧但保留溢出区」也被否决——那等于把 ADR-0006 刚删掉的「其他」分组换个名字请回来。还考虑过「顺手删掉 `subjects` 表，作业直接存科目名」，否决：那是不可逆的表变更，收益只是少一次 join。

**后果（必须记住的四条）**：
1. `--c-s7..s12` 在常规路径下不再有读者（明/暗两组共 12 行 token，唯一的引用者是 `ui.js:11` 的 `idx % 12`；六行科目只走到 s1..s6，正好与 `--c-yu..--c-sheng` 六个别名逐一对应）。按"只留不删"处理：它们是上一轮锁死的取值表的一部分，而第 6 条保住了表外科目的读法，数据修复带进来的第七行仍会取 s7。ADR-0004 后果 1 那条「第 13 个科目撞色」的待办因此被**推远而未关闭**。
   > 〔002 回写，2026-09-25〕那六行**别名已删**，`--c-s7..s12` 十二行仍"只留不删"。删别名不是清理死代码，是主题化的硬前置：别名只在 `html` 上声明，`var(--c-s1)` 在 html 的 computed-value time 就定死了，`body.theme-*` 覆写 `--c-sN` 追不动它们——留着它们，任何写 `var(--c-yu)` 的新规则都会在暗档和所有主题下渲染成白板风亮档红。判据落在门禁 `§7(a)-7e`（反向断言：`style.css` 里不得再出现别名定义），细节记在 ADR-0012 与 spec §2。
2. `MAX_SUBJECT_NAME_LEN` 失去读者（名字必须在六科内，长度校验没有对象），随本 ADR 一并删除。
3. 门禁与账本要跟着改，否则"通过"是假的：`verify-47b.js` 故事 27/29 的正向断言改写为反向（六科之外录不进、候选框已不存在），故事 28 换形为"点已录科目 = 切到那一条且不弹确认"；`verify-47c.js` 故事 45 的 README 关键词表去掉「自动建科」、换成一条"README 不再承诺自由输入"的反向断言；`verify-027.js` 那七格负载（唯一能压到降级阶梯的形状）不能再靠 POST `subject_name:'政治'` 造，改为直接用 SQL 往临时库种（`.scratch/seed-subject.js`），并加一条"该 POST 必须 400"的断言，让静默失效变成响亮失效。`tools/build-portable.sh` 内嵌的绿色版 README 有两句承诺要改写。
   > 实施时发现这四个脚本还带着**上一轮之前**的形状：`verify-47b.js` 的故事 33/34/31 在给单科灌 14/26 条（ADR-0005 起就是 409，`mk()` 直接抛错），故事 34/34b/37 还在量 `show-carousel`/`#showPages`/`advanceShowPage`（ADR-0007 起已删）。既然本轮要把门禁改到能跑，这几处一并翻面成今天的架构：负载改为"每科一条、每条多段长文本"，极限判据从"走轮播不滚动"改为"允许滚动，但必须是 `show-scroll-fallback` 兜底档且不得静默裁切"，并补一条"轮播那套节点一个都不该留下"的反向断言。`verify-020.js` 整份作废（它逐条测的就是被删掉的那 49 行链），判据搬进 `verify-47b.js` 故事 28。
   > 真跑起来又挖出四处，都记下来，因为它们全是"判据在骗人"而不是产品缺陷：
   > ① 第 4 条那句"历史数据仍会上墙"有一个前提没写下来——**要整页重载**。分组的依据是 `state.subjects`，而 `loadSubjects()` 只在 init 调一次，不在 5 秒轮询路径上；只调 `loadHomeworks()` 的 `verify-47b.js` 故事 31 因此永远停在旧名单，"颜色池被复用"这件事根本没发生。② 降级阶梯的三条判据（47b 33/33b、47d 33c）原先都是"基准 → 一步压到极限"，跨过了第一档那两行宽的窗口，读到的是 `dense`+`fit=0.55`，看着像"没有第一档"；改成逐行扫负载后四档顺序一目了然。同一段还必须先扫阶梯、后种表外科目：常驻格子跟着 `subjects` 走，先种满九格，"六格短文"这个基准其实读出来就是 dense 档。③ `verify-47a.js` 故事 9 读控件自身的 `display`（展示态把控件藏在祖先容器上，于是永远"泄漏"）、故事 20 点 ADR-0006 删掉的 `.row-action-btn.edit`（点击被 `catch` 吞掉，只能报"需人工确认"），故事 25 那发删除等 CDP 回包导致整张闸超时中断——三处都按 47b/47d 已有的写法修齐。④ `verify-47c.js` 标着「·触控」的那几档是 `rig.media({hover:'none'})` 伪装的，Chrome 不吃这个模拟（实测 `hoverNone` 恒为 false），账本改标「伪触控轴，真轴见 47d」；真触控轴那档另加 390×844 竖屏（六按钮 95×48 两行三列、保存在屏内）。顺带：47c 故事 47 只认字面量 `ADR-0002`，而 `db.js` 写的是 `docs/adr/0002`，判据放宽到两种写法都算指回。
4. ADR-0006 关于「新科目照样能建、照样上墙，只是排在表尾」的前半句自本 ADR 起失效，后半句（表尾次序按 `subjects.id`）继续有效，作为历史数据的读法。
