# 绿色包的说明书与溯源：人工同步两份文档，戳记落在产物侧

2026-09-25 出包前定的两件事，一起记，因为它们回答的是同一个问题：**这份要被拷到教室一体机上的包，谁替它负责说清楚自己是什么。**

**决定 1 · 包内说明书走人工逐条校，不做单一事实源。** `release/**/README.txt` 的文本源内嵌在 `tools/build-portable.sh:132-260` 的 heredoc 里（本轮补丁后的新坐标；旧坐标 `:103-178`，而本 ADR 其余各处引用的 `:37`/`:94`/`:205` 仍是**补丁前**的形状，未随平移——按项目惯例「文档里的行号是实施前坐标」），与仓库根的 `README.md` 是**两份文档**；本轮选择出包前把那 76 行逐句对着代码核一遍，**显式否决**"让脚本从 `README.md` 抽取生成 `README.txt`"。

**决定 2 · 溯源戳记落在产物侧。** 包内新增 `BUILD.txt`（commit 短哈希 + 构建日期 + 出包那一刻的门禁读数），zip 文件名带日期；**显式否决**"提 `package.json` 的 `version`"与"把版本号露到界面上"。

## 为什么

- **说明书这一份必须自带说明书**：接包的人只看 `README.txt`，不在仓库旁边。而本轮实测缺口不是"措辞旧"，是**整族功能没提**：脚本全文 grep `主题|暗档|玻璃|暗色` **0 命中**，界面上却是工具行两颗钮（`index.html` 的「暗色模式」、`ui.js:404` 写出的「主题 · 当前档」）；`:120` 说"闲置 5 分钟会自动弹回展示态"，却没说 `ui.js:483 EDIT_IDLE_WARN = 240` 意味着**第 4 分钟起就有预告 toast**；主题/暗色/字号/展示倍率全存 `localStorage`（`main.js:34`、`ui.js:363/396`），**不在 `homework.db` 里**，换浏览器即全部重设。
- **不做生成，是因为两份文档的读者不同**：`README.md` 混着仓库结构（`:72`）与门禁口径（`:141` 的 `§7(a)-6`），要抽取先得拆出一份纯使用者块——那是改工具链的一张票，不该塞进出包这一轮。人工同步的代价照付，并显式挂账（见「后果」）。
- **不用 `version` 是因为它对外不可见**：`package.json:3` 的 `2.0.0` 自基线提交 `d039837` 起一次没动过，于是 9/19 那份包与本轮新包**字节同标签**，而后端逐字节相同、前端差 591 行改动（`style.css` 473 + `ui.js` 67 + `main.js` 41 + `index.html` 9 + `state.js` 1）。而 `public/` 全量 grep `version` **0 命中**——那个号只有去开 `package.json` 才看得到，交给别人等于没写。界面露版本则要过 `test/style-invariants.test.js` 的 `§7(a)` 那一族（新增可见/可点节点撞上命中区与 token 在册两条判据），且"展示态要不要露版本"本身是一个需要新 ADR 的形状问题。

## 后果（四条，前三条是本轮已接受的账）

1. **两份 `README` 没有机检，靠人工同步。** 项目里已有同族机检的写法可抄（`§7(a)-7c` 拿"JS 数组 = CSS 块 = 非 HTML"三处对齐），但那种判据只能做到"关键词在场"级别，措辞漂移会漏报。**本轮显式不收此项。** 〔出包后追加一处收紧，见「出包实录」第 3 条：档数与档名这一格已进门禁，**其余措辞仍无人管**，本条不销账。〕
2. **本包带着已知未闭合项出门，是第二代**（9/19 那份同样带着）。目标设备是**触控一体机**，而 `README.md:141` 那句"逐处逐档的实测几何在展示态与主题弹层上仍待教室真机复测（旧实测读数出自主题化之前，那时弹层还不存在）"对这台机器**适用**，不是不适用。第一次在触控机上点主题弹层如果不好点，就是本包的第一个真机风险。
3. **`release/` 被 `.gitignore:12` 整目录排除**，出包的破坏性动作（`:37 rm -rf "$DIST"`、`:205 rm -f "$ZIP"`）删掉的东西 git 取不回来——"工作树干净"在这里不代表有安全网。因此出包前**先改名留档**旧产物（9/19 目录实测 96,899,234 字节、zip 36,695,738 字节），代价是 `release/` 里同时躺着两代包，认版本要靠文件名与 `BUILD.txt`。
4. **产物名带日期与本 ADR 之前的一切引用形状不再一致**：全仓 grep `homework-tracker-portable` 在 `README.md`/`CONTEXT.md`/`docs/**`/`.rivet.md`/`AGENTS.md` 里 **0 命中**，所以改名不撞文档；但 `.scratch/` 下的旧工单结论（尤其 ticket 028）里那份产物路径从此读起来是上一代的形状。

## 读数的三态（本 ADR 只用已实算的那些）

- **已实算**：脚本 grep 主题族 0 命中；`README.txt` heredoc 与 `release/homework-tracker-portable/README.txt`（9/19 18:01）**逐字节相等**（2102 字符）；后端 `server.js`/`db.js`/`package.json`/`api/` 与 9/19 包逐字节相同；前端 5 文件 591 行改动；`node --test` 105/105；本机与旧包 `node.exe` 同为 v24.15.0、`better_sqlite3.node` 同为 1,891,328 字节（无 ABI 变更）；旧 `start.bat` 481 字节不含 UTF-8 中文字节且 `iconv -f GBK` 可干净解出 → `:94` 那条 GBK 分支上次生效、本机 `iconv` 在位；`public/` 现 9 文件、旧包亦 9（主题化未新增文件）；`release/` 合计 156,338,572 字节、D: 剩余 66,047,078,400 字节；`.scratch/四主题体系/geom-toolrow.json` 的 `entry.btn` 97.6×44、弹层单项 95.6×48，且用 `--blink-settings=primaryPointerType=2,…` 量得。
- **仅本机抽样**：上述弹层与入口几何出自**本机 Chrome**，非教室一体机；两代触屏读数的关系本 ADR 不作断言。
- **未量**：教室机上的触屏逐档几何（挂 `README.md:141`）；`:is`/`:where` 门禁旁路（挂 `docs/specs/2026-09-25-theme-system-four-themes.md:167`）；9/13 那份 `.7z` 老遗留（ticket 028 已记）。

## 出包实录（2026-09-25 15:18 那一份，与本 ADR 同一天）

1. **发出去的是 15:18 那次构建，而它比脚本的当前形状少两句说明书。** 门禁前置那段在 15:26 之后连续拦住两次构建，红点不在打包这一路：另一路会话在 15:20-15:26 之间往 `public/style.css` 落了 Discord 主题两块（+160 行，未提交），`§7(a)-8b` 实测该块 `--bg=#ebedef` 对 `--c-s4 #0d8574` 只有 3.87、对 `--c-s6 #2f8a2e` 只有 3.73（门槛 4.0）。两次中止都落在 `rm -rf` 之前，`release/` 里 15:18 那份与 `release/archive/` 的三件留档一行没动——门禁排在删任何东西前面的理由，由此拿到一次真实读数。
2. **15:18 那份带着一句已知不实的话出门（使用人当场裁定"先交这份"）。** 说明书【怎么用】里那句"那个黑窗口里的提示是英文"，与同一份包起来后实测的三类内容不符：启动脚本的英文 → `db.js:164` 的 `✅ SQLite 数据库初始化完成 → …` 加 `server.js:13-14` 两行中文 → 之后每轮页面自动刷新滚两行访问记录（`api/index.js:104` 逐请求记一行，展示态 5 秒一刷）。改正的三行已在脚本 heredoc 与文本源里，**下一次成功构建才会带上**；在那之前拿到这份包的人读到的都是旧句。那句的功能指引本身没错（窗口一直开着 = 服务在跑），失真的是"都是英文"这个描述。
3. **档数与档名这一格从"没人管"变成"对不上就不出包"。** 逼出这条判据的正是上面那批在飞改动：`ui.js:371` 的名单已从 3 个变成 4 个，而说明书还写着三套。自检因此新增：包内 `ui.js` 的 `THEME_NAMES` 长度要等于说明书那句「主题一共 N 套」的 N，且 `THEME_LABELS` 里每个中文档名都必须在说明书里出现过。牙齿双向都验过——三主题名单 + 新正文 → 过；四主题名单 + 同一份正文 → 拦下并指名"说明书说 3 套，名单里却是 4 个（白板/GitHub/Discord/玻璃）"。**这是对"只打包、其余全挂账"这条共识的一处超出**，理由是它只在出包那一刻多花一次字符串比较、不改任何产品形状；后果 1 的账不因此销掉。
4. **两份 `.txt` 的行尾与 BOM 是探针挖出来的洞，不是设计出来的。** 上一代包的 `README.txt` 实测「有 UTF-8 BOM、76 行全裸 LF」，本轮初版 `BUILD.txt` 更是连 BOM 都没有；纯 LF 在只认 CRLF 的记事本里会把整份说明画成一行。脚本因此加了归一步（BOM + CRLF）与自检里的字节回判。判据为什么用 node 而不是 shell：本机实测 MSYS 的 `grep` 与 `gawk` 读文件时把 `\r` 当行尾吞掉，拿它们判行尾会把已经是 CRLF 的 `start.bat` 也误判成 27/27 行裸 LF——**自证用的工具自己不可信时，读数得换一个按字节的实现**。
5. **机器侧冒烟读数**（不碰真机、不写真实库）：包整个复制到含中文与空格的 `%TEMP%` 路径后，`start.bat` 逐行干跑（只把开浏览器 / 起服务 / `pause` 三行换成 echo）→ 正文逐字节 ASCII，`cd /d "%~dp0"` 与 `%~dp0node.exe` 在中文+空格路径下把包内那颗 node.exe 正确跑起来（v24.15.0），URL 行与 README 指路行各就位；服务用 `DB_PATH` 指到临时库 → 首页 200（7335 字节）、`/api/subjects` 返回补齐后的六科、`/api/homeworks?date=…` 返回空表、临时库实测 6 科目 0 作业，**包目录里从头到尾没有长出 `homework.db`**；zip 与目录逐文件比 → 986 个文件、清单双向差集为空、986 个 SHA-256 全等。
6. **一处读数纠正了顺手的假设**：同一次 cmd 运行里 stdout 是**两种编码并存**的——cmd 自己 echo 那个中文目录名走代码页 936（10 字节 GBK），包内 node 打 `process.cwd()` 走 UTF-8（15 字节），合计 25 个非 ASCII 字节，`iconv -f GBK` 解到中间就报 cannot convert。所以"整段输出按一个代码页解码"这种判据本身就是错的，改成了 bat 正文与 cmd 的 echo 各判各的。真控制台里那几行中文与 ✅ 显示成什么样，本机用管道复现不出来（Node 对控制台句柄与对管道走的是两条写入路径），归入下面的未量。
7. **顺带记一笔 CSS 事实**：`theme-whiteboard` 这一块**不存在**——白板按 ADR-0012 就是"`<body>` 不带任何 `theme-*` 类"那张脸，而 Discord 已经在册（`body.theme-discord` + `.dark-mode` 两块，只是没进说明书口径）。任何"在册块数 = 名单长度"式的对齐判据在白板这一档上必然空转，别照抄 `§7(a)-7c` 的形状。
