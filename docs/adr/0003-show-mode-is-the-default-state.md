# 展示态是默认态，全屏与模式状态解耦

一体机刷新、重开机、上课中途 F5，一律落在**展示态**；编辑态必须显式进入（点"退出展示"），且闲置超时自动弹回展示态。曾考虑过两个方向相反的方案：记住上次模式（localStorage），以及给编辑加口令——前者会在刷新瞬间把满屏删除钮暴露给全班，后者与 ADR-0001 的零鉴权前提冲突，均被否决。

同时决定：**继续用浏览器 Fullscreen API，不改成纯 CSS 仿全屏**（投影需要那一条地址栏的高度）。冷启动无用户手势导致 `requestFullscreen` 被拒是**预期行为**，由一次性"首次触摸即补全"监听兜底，不弹任何遮罩打断上课。

**关于 Esc 的硬约束**：网页无法取消浏览器层的"Esc 退全屏"，Fullscreen API 不提供该开关，`preventDefault()` 亦无效。因此本项目的立场是**解耦而非拦截**——按 Esc 只掉全屏，**不改变展示/编辑态**（展示态本就不依赖全屏，仅损失一条地址栏高度）；同时收回我们自己实现的那半个 Esc：模态不再响应 Esc 关闭，因为它与遮罩点击一样会静默吞掉已输入内容。曾考虑"按 Esc 时同步退回编辑态"，被否决——那会让一次误触把满屏删除钮送到全班面前。

**后果**：闲置自动回弹的计时器在模态打开或输入活跃时必须冻结，否则会把科代表正在打的一半内容吞掉。
