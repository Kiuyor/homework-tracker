# 作业墙只回答"今天有什么"

曾考虑让墙承担核对职责（标记完成）、备注职责（note 字段）、批量职责（批量导入 + 多选改科目）。最终全部移除：科代表的使用场景是"被学生提醒后上来改一两条"，这些能力要么写进去看不见（`completed` 与 `note` 都只进不出，渲染层从不读），要么其入口在触控屏上偷走了比它们价值更高的东西——屏高与注意力。录错了就逐条改。

**备选方案**：把 `completed` 渲染成删除线+灰化（展示态也生效），使其成为真功能——被否决，因为"哪条已交"不是这面墙要回答的问题。

**后果**：删除的是**能力，不是存储**。前端与 `/api/homeworks/batch` 路由连同其专属测试一并移除；但 `homeworks.completed`、`homeworks.note` **两列原地保留、不再有任何写入方**——便携版会带着一个装有真实数据的 `homework.db` 分发出去，而本项目只有幂等 DDL、没有 migration 账本，为两列沉默的字节对未知用户数据做不可逆 `DROP COLUMN` 不值，且 `AGENTS.md` 把这类操作列在先说明后确认的闸门之内。**拖动排序（`/api/homeworks/reorder`）不在此列，它回答的是"哪条更显眼"，保留。** `db.js` 中这两列旁须留一行注释指回本 ADR，表明"列还在但没人写"是决定而非遗漏。后续读者不应试图"补回"批量与完成态界面，除非本 ADR 被取代。

> **加粗那句已被 [ADR-0006](0006-wall-order-is-a-fixed-subject-table.md) 推翻**（2026-09-19）：一科一条之后"哪条更显眼"这个问题不再存在——一天之内每科至多一条，没有同科可比。`reorder` 路由与 `drag.js` 已删除，访问该路由返回 404。
> 本 ADR 关于 `completed`/`note` 两列"保留列、无读写方"的处置**不受影响且被沿用于新增的那一列**：`homeworks.sort_order` 现在也是"列还在、没有读者"（顺序改由主科优先表决定），理由与上面那句一模一样。
