# Discord 那一档的取值是裁下来的，不是抄来的

2026-09-25。工单 003 的 Discord 半边（`body.theme-discord` 与 `body.theme-discord.dark-mode`）落地时遇到的不是算术问题，是**出处问题**：ADR-0012 决定 6 说品牌档的取值「逐值照抄官方优先」，而 Discord 这一家**没有可解析的官方源可抄**。本 ADR 记下这件事怎么解的，以及它换来哪几条纪律。

## 背景：三条取证路都堵（读数记在 `.scratch/四主题体系/contrast-baseline.md` §5）

- `discord.com/branding` 与 Discord CDN：连接失败（000）。
- npm 不存在 Discord 的颜色 token 包（搜 `discord brand colors` / `discord theme palette`，命中只有 `discord-api-types`，无 UI 色值）。
- `raw.githubusercontent.com` 不通；`api.github.com` 的 code search 需鉴权，未鉴权命中的全是无人维护的镜像（★0）——拿它当出处比拿记忆当出处更糟。
- 结构性事实：GitHub 有公开的 design-token 产物（GitHub 两块就是从 `@primer/primitives@11.10.0` 逐值机检的），**Discord 没有**——它的 `--base-*` 一层从来只存在于客户端包里，且是混淆产物、随版本变。

**所以「Discord 的官方值」这个概念在本站不成立。** 这不是"还没找到源"，是"这个源不存在"——它会随着每一次想给 Discord 补版本戳的冲动重新出现，所以写进 ADR 而不是只留在票面。

## 决定

1. **Discord 两块的取值由用户裁定**（2026-09-25 三锚点：暗档底 `#1e1f22`、动作色 blurple `#5865f2`、亮档"白卡浮在 `#EBEDEF` 上"）。它们对这两块有约束力，但对「这是 Discord 官方值」这句话**没有**约束力。
2. **裁值不冒充抄值。** 两块 Discord 里**一行官方 token 名标注都不许出现**，头部注释写的是"取材口径=用户裁定、无可解析官方源、引用本 ADR"。这条由门禁执行而非由自觉执行：出处机检（`test/token-provenance.test.js` 的 T2）有一份 `SOURCES` 在册表，只列 GitHub 两块；**不在册的 `body.theme-*` 块一旦出现 `--x: #hex; /* --官方token名 */` 或 px 换算标注就判红**（靶子 `discord_annot.css`）。判红的理由不是格式错，是**伪造出处**——它会让下一个人拿一个不存在的东西去"核对"。
3. **决定 6 对无源档改为「复用锁死组 + 裁值」两栏，而不是一律照抄。** Discord 两块的十二个科目色仍**逐字等于**所在明暗梯的锁死组（`:root` / `body.dark-mode`），这条由 `§7(a)-9d` 以**值相等**执行（不是各自 ≥4:1——那个判据防不住"有人顺手优化了一个 hex"）。除科目色之外的 ink/accent/语义一族才是裁值，代价见下面第 5 条。
4. **裁值撞上门禁时，改判据基准的必须是"判据读的那一层"，而不是裁下来的那个值。** 灰桌 `#EBEDEF` 作页底把 `§7(a)-8b` 当场判红（前排 s4 **3.87** / s6 **3.73**，地板 4.0）。三条路里选的是 (a)：**内容刷白卡、灰桌只留页面底**——`#EBEDEF` 一字未动当 `--bg`，另加两条主题覆写把科目色与顶栏抬到 `--surface` 上。连带改掉的是一条判据的形状：

   > **`§7(a)-8b` 的基准从「块自己的 `--bg`」改成「科目色实际坐在哪一层」。** 现推法：默认基准是本块 `--bg`；若存在 `body.theme-X[.dark-mode] .subject-group { background: <token> }`，基准就是那个 token 在本块里解析出的值（按源码顺序取最后命中的；暗档专属覆写**不被亮档继承**）。读不懂的形状一律回落 `--bg`——回落会让 Discord 亮档判红，所以这条保守的方向是**响**，不是静默放过。
   >
   > 故事 8 与 CONTEXT「实底」那条要钉的从来是**颜色对**，不是 `--bg` 这个字段名；这一档是它第一次与字段名分家的场合。

   配套新增 `§7(a)-8c`：反向盯住那两条覆写规则**还在、且值还是它**。只留 8b 不够——覆写被删掉时 8b 会静默回落去量 `--bg`，把"选择器被人删了一行"读成"这一档不达标"，报的是颜色账，读的人想不到真正的原因。三条靶子各证一格：`no_discord_card.css`（8c＋连带 8b）、`discord_topbar_desk.css`（**只有 8c 响**，所以 8c 必须盯两条规则不是一条）、`discord_dark_only.css`（只有 8b 响，验暗档专属那一支）。

5. **blurple 在暗档不作 accent。** `#5865f2` 压在 `#1e1f22` 上 **3.58**、`#2b2d31` 上 **2.99**，两个背衬都不作文字；它作填充压白字是 4.61（过 4.5）。ADR-0012 决定 6 预留的"锁用途"（只能当填充底配 `--on-accent`）在这里**不适用**——本站的 accent 承担五处组件角色（焦点环、选中态、入口钮、滑块、活动描边），锁不住。所以暗档取同族提亮的一支（`--accent: #a8b3ff` / `--accent-strong: #c8cffd`，两个背衬上 8.28/6.93 与 10.83/9.06 全过），亮档**保留 blurple 原值**（白卡上作文字 4.61、灰桌上作焦点环 3.93 走 3:1 非文本判据，两条都在各自的窗内）。
   **代价写在块头，不糊过去：暗档认不出 blurple。** 色相角实测 `#5865f2` 234.9°、本档 `#a8b3ff` 232.4°、白板暗 `#99a8ff` 231.2°——差 2.5° 与 1.2°，是同一族淡紫蓝里的明度/饱和差，不是两个颜色；但色相角差量的本来就是错的轴（只降明度可以让 Δh 保持 0° 而把"绿"做成"黑绿"，见底账 §7 那条批评），所以**"这一档像不像 Discord"归 007/008 由人裁一次**，不由那三个数裁。逃生口（把 blurple 塞回 accent 位 + 一次 `ACCENT_ALLOWED` 扩表）**登记但没走**：它换来的是一档 2.99 的文字色。

## 本 ADR 不改的东西

ADR-0012 决定 1（主题 × 明暗正交，八块）、决定 2（骨相只活在 token 层）、决定 3（成套完整声明）、决定 5（材质只在浮层）、决定 7（名单只有一份）全部原样有效——Discord 两块与其它档走同一套机制，`§7(a)-7a/7c` 一视同仁。ADR-0009（动作色只给可点击）在本档**未被触碰**：blurple 落的位置全是 accent 角色位，内容区一处没有。ADR-0011（科目六科闭集）与 ADR-0013（入口是一颗按钮）同样不变。`--show-*` 与 `--sp-*` 一字未动（本次 `public/style.css` 的 diff 是 **164 插入 / 0 删除**，diff 里 `--show-` 命中 0 处）。

## 后果

- **多出一类"无源档"的写法。** 以后任何品牌档如果同样取不到可解析源，形状就是本档这套：裁值进块、`SOURCES` 不加行、块头写"取材口径"而**不写** token 名、复用梯的科目色交给 `9d` 比值相等。要照抄官方的档则相反：必须进 `SOURCES`，且块内每条 hex 声明都要带标注（T2 的完整性判据）。这两族在同一份 CSS 里并存，靠 `SOURCES` 那张表区分，**没有第三种形态**。
- **门禁的判据里出现了"层"这个概念。** `§7(a)-8b` 从此读一条覆写规则的输出而不是读一个字段，`§7(a)-8c` 因此必须存在。这是本次唯一一条**放宽既有断言**的动作（原断言更简单也更容易成立），所以它两处删除都配了反向断言与靶子，不是删掉了事。
- **投影墙的形状变了。** 路线 (a) 让 Discord 亮档在墙上读作「灰桌上六张白卡」。面板感只用色差与圆角——白卡对灰桌只有 **1.17:1**，所以**不补边框、不加投影**（补上去也看不见，`--line` 对白卡是 1.35）。这仍然是骨相层的改动，不是布局分叉（spec §8 那句原样有效）。观感归 008 由人裁。
- **那条 `padding` 有一处不在配色账里的连带，本 ADR 记它是因为门禁看不见它。** 卡片规则带的 `var(--sp-5)` 内边距在展示态同样生效（`body.view-show .subject-group` 不声明 padding，两条不冲突），而 `fitShowDisplay` 判的是 `.subject-group` 自己的 `scrollHeight > clientHeight`（`ui.js:628`）——全局 `border-box` 下 16px 上下内边距把内容盒压掉 **32px**，于是这一档的降级阶梯**可能**比另外三档早 32px 触发。决定 2 那句"`--show-*` 只许改名不许改值"**挡不住这件事**：一个值都没改，改的是它前面那点空间。归 007 用一次切档对照裁掉这个"可能"（问法记在 003 票面遗留①）。
- **`--ink-faint` 那条待裁项没有被本 ADR 解决**，只是多了一个事实：八档 × 两底 16 格里 13 格不达 4.5，过线的是 Discord 暗档两底（5.87 / 4.92）与 Discord 亮档的**白卡那一层**（4.83；同一颗色在灰桌上 4.12 仍不达）。别的档一格没动、门槛没降，交回 008 的还是那一句原话（换到 `--ink-dim`，还是把 `--ink-faint` 抬到达标）。
- **待办（不在本 ADR 内）**：007 的运行时账本要按八档重跑（形状 12→16，两支探针都读 `window.THEME_NAMES` 现推，不用改代码）；003 票面里"名单只填到 3"那几处计数已按实际在册块收口。
