# 一科一条：作业与科目在每一天上一一对应

真实数据给出了答案：`homework.db` 里 8 个上课日、42 条历史作业，**每一个「日期 × 科目」组合都恰好一条**，从来没有第二条；`subject_id` 为空的条目 0 条。"一科多条"这个我们一路支持的能力，在真实用法里一次都没被用过。现决定把它从能力清单里拿掉，并升级为系统强制的规则：

- 数据库加 `(date, subject_id)` 唯一索引，真约束，不只是界面好看。
- 「添加作业」仍在，但选了当天已有作业的科目时，模态直接预填那一条并走 PUT——**入口不产生冲突**。
- 撞车时（并发、多标签页）后端返回 409，绝不静默覆盖。
- 「其他（无科目）」分组一并取消：科目必选，`resolveSubject` 的空科目分支与渲染兜底删除。
- 一门课当天要留两件事，靠这一条正文里的换行表达（真实数据里 5/60 条本来就这么写）。

**取舍**：备选是"软默认——界面只给一个入口但数据层不管"，被否决，因为那样仍然要为多条写渲染兜底，规则形同虚设；也考虑过"只在界面约束、数据库不加索引"，被否决——零鉴权的单机工具里，唯一索引是唯一能防止脏数据的东西，而它便宜。回退代价显著：撤掉索引、恢复行内多条渲染、把「其他」分组请回来。

**后果（必须记住的三条）**：
1. 加索引那次启动若发现重复行会直接失败。当前唯一的一批重复是验收时灌进去的测试数据，已决定先清掉；迁移**不写合并逻辑**——真实历史里没有需要合并的东西。
2. 工单 015（单科 12 条超载被静默裁切）的成因被这条决策抽掉，作废；残留的问题变成"单条正文过长"，另开票。
3. `api/index.js` 里"显式 `subject_id:null` 归入其他"那段注释与 `ui.js` 的无科目兜底同批删除，别留"以防历史数据"的注释——历史数据是 0 条。
