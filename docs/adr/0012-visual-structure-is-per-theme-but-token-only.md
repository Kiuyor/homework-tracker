# 视觉骨相改为每套主题一份，但主题只能活在 token 层

2026-09-24 一轮「给项目增加 GitHub / Discord / 液态玻璃三套主题」的对齐。ADR-0008 把「引入卡片 / 底色 / 纵深」和「品牌识别色」列为已否决备选，并写下「今后任何让墙更好看的诉求只能在 token 层与层级解决，要推翻需新 ADR 显式作废」。主题化正面撞这条：Discord 的深底面板与玻璃的半透浮层在 ADR-0008 下都不成立。

**本 ADR 显式作废 ADR-0008 被否决清单里的两条**——第 7 行「引入卡片 / 底色 / 纵深」与第 9 行「品牌识别色」（每套主题都有自己的动作色）。第 8 行「翻转为暗色默认」**继续有效**：默认主题仍是白板风。ADR-0008 第 13 行那条后果被本文件第 2 条改写。

六条决定一并生效：

1. **主题 × 明暗是二维正交，不是五选一名单**。四套主题（白板风 / GitHub / Discord / 液态玻璃）各有明、暗两档 → 8 个 token 块。暗色钮、`hw_darkmode` 存储与 `prefers-color-scheme` 回退（`main.js:213-220`）一字不动；新增 `hw_theme`，**不跟随系统**——系统没有主题信号，只有明暗信号。
2. **骨相边界收在 token 层外观属性集**：颜色、圆角阶梯 `--r-*`、边框、投影、`backdrop-filter`、字重、控件形状。**不含** DOM 结构、网格布局、断点；展示态那组 `--show-*` 承重层照旧只许改名不许改值。这是 ADR-0008 唯一原样继承下来的那条。
3. **每个主题块把自己那一族 token 说满，不做级联回落**（缺一项即失败）。范围**限外观族**：颜色全族（`--bg/--surface/--ink*/--line/--accent*/--on-*`、语义色、`--c-s1..--c-s12`）+ 圆角阶梯 `--r-*` + 材质 `--glass-*`/`--floor-alpha`；逐条名单见 spec §2。**不含 `--sp-*` 与 `--show-*`**——前者是跨主题唯一的间距阶梯，后者被上面第 2 条钉成「只许改名不许改值」，把它们算进「必须重声明」会与第 2 条自相矛盾。
4. **科目色从「两组锁死」改为「八档各自锁死」**——「各自锁死」是判据形状的变化，不是重算的授权：**八档全部复用现有两组锁死六色，一个 hex 都不重算**，代价换成一条门禁（见决定 4b）。同一科目跨主题**保持色相族**（语文永远是红族），只调明度与饱和，保住科代表与学生的颜色记忆。
   **〔001 回写，2026-09-25〕** 上面这句原写作「GitHub 与 Discord 的四档可直接复用…真正需要新算的只有玻璃档」，前提是手敲 hex 的实算。工单 001 改从文件解析取值重跑（底账 `.scratch/四主题体系/contrast-baseline.md`），三条订正：
   - **GitHub 两档确认复用**——亮档六色在 `#ffffff` 上 4.38~5.18、`#f6f8fa` 上 4.11~4.86，暗档六色在 `#0d1117` 上 7.44~11.18、`#151b23` 上 6.81~10.23，门槛 4:1 全过。此前那组读数与解析式复跑**逐位一致**：算式没问题，错的只在个别输入。
   - **「需要新算的只有玻璃档」被推翻**——玻璃也不重算，条件从「换色」变成「`--bg` 落窗」：亮档 `#f2f5f9` 最坏读数 4.00（压线），`#eef2f7` 起就败（3.90）；暗档窗口很宽，到 `#232830` 仍有 5.83。
   - **两处输入被官方包推翻**：`canvas.subtle` 暗档写作 `#161b22`，`@primer/primitives@11.10.0` 实为 `#151b23`；暗档链接蓝写作 `#58a6ff`，实为 `#4493f8`。这正是〔手敲输入〕那条风险的兑现。
   - **未闭合的那一半换了性质**：Discord 两档**判定不了**，但理由不是比值不过，而是「Discord 官方值」这个概念没有出处可解析（见决定 6 的回写）。原句那段立论依据（亮档六色落在 `#313338` 只有 2.44~2.89、暗档落在它为 4.97~7.47）与本条上一条同性质——**输入是手敲的、无源可核**，读数本身不再作为「亮档不能复用」的理由。它不进验收账本，也不当作已证。

4b. **玻璃档的 `--bg` 落窗是一条门禁，替掉「重算六色」**。任一 `body.theme-*` 块的 `--bg` 相对**该块自己那组六色**的最坏读数必须 ≥4:1，断言跑 CSS 文本、与底账矩阵脚本同一套数学——于是 `--bg` 被人改暗时判红的是**颜色对**，不是记忆里某个数。
   **〔002 落地，2026-09-25〕** 这条在 GitHub 亮档上第一次真的选中了一个值：`--bg` 取 `--bgColor-muted`（`#f6f8fa`）时表外科目色 `--c-s7` 3.85、`--c-s9` 3.82 掉出窗口，取 `--bgColor-default`（`#ffffff`）时十二色最低 4.06 全在窗内。于是「照抄官方」在此处不是抽象原则而是有唯一解——官方那两值的分工本来就是 default 作页底、muted 作卡片，我们只是没有记反。窗口此刻由 `§7(a)-5c` 的逐字钉死守住，`--bg` 落窗这条通用断言本身留给 004（它才有玻璃档要量）。
   **〔003 兑现，2026-09-25〕** 那句"留给 004"被推翻，理由不是排期而是判据归属：这条断言只读 CSS 文本、不需要任何新块，留在 004 就等于让"块顺序/名单"这类结构断言先进门禁、而唯一一条**算术**断言后进入门禁。现在它是 `§7(a)-8b`，覆盖全部四个在册块（含白板亮/暗两块，不只是主题块），`--bg` 非实色时不许静默跳过。配套 `§7(a)-8a` 先把数学自证（四个已知读数 21.00 / 4.54 / 8.61 / 8.08，第四个刻意挑 `#ff7a6e` 压 `#010409`：它的 1/4/9 三个通道走 `/12.92` 那条线性分支，前三组一个都碰不到）——门禁里第一次出现 WCAG 算式，判红之前得先证明算式没写反。门槛取 **4.0 而非 4.5**：白板 `--c-s6` 在白底只有 4.38，抬到 4.5 要先改承重层，那是另一次裁决。"会不会判红"由 `dim_bg.css` 变异体证明（把亮档 `--bg` 换成官方描边色 `#d1d9e0`，只有 8b 与其连带 5c 响）。
5. **玻璃的材质只允许出现在浮层**（顶栏、弹层、浮条、toast）；科目内容区落在一张有 α 下限的**实底**上（亮档 ≥0.92、暗档 ≥0.88，进 token）。理由是一条数学：玻璃底的亮度由壁纸决定，同一个色在中灰 `#808080` 上亮档只有 1.11~1.31、暗档 1.55~2.33——**没有哪个 hex 能在亮度不明的底上稳定 ≥4:1**。要保住「后排看得清」这个不变量，就得让科目色所落的底是一个已知亮度。
   **〔001 回写，2026-09-25〕** α 阶梯跑完（底账 §3，五档背衬取 min~max）后，这条的两个数被拆开，一个保留、一个换了管辖对象：
   - **暗档 ≥0.88 保留**，实测边界落在 0.82~0.85 之间，0.88 有余量（`--ink-dim` 5.03、`--c-s1` 5.18）。
   - **亮档 ≥0.92 作为「科目色压在透明底上」的下限不成立**：0.92 时 `--c-s4` 3.80、`--c-s6` 3.66，抬到 0.95 时 `--c-s6` 仍只有 3.92。**只要科目色允许出现在半透浮层上，亮档就不存在任何达标 α**——这是 Class B 死锁，不由数值解决。
   - 它由**结构**解决，而且代码里此刻已经成立：科目色只由 `ui.js:78`（墙上格子）与 `ui.js:108`（作业行）写入，两处都是内容区，模态里没有科目色。于是本条真正新增的不是一个数，是一条禁令：**科目色选择器不得挂在带 `backdrop-filter` 的层上**（门禁做反向断言）。内容区的 α 压在已知 `--bg` 上是 Class A，归 4b 那条窗口断言管。
   - **亮档 ≥0.92 继续成立，但对象换成浮层上的文字**：`--ink-dim` 在 0.88 的白玻璃上只有 3.82、0.92 才到 4.20。即「0.92」从内容底门槛变成浮层文字门槛。
6. **品牌官方 hex 逐值照抄，优先于本站门槛；冲突处锁用途而不改色值**。实算：Discord blurple `#5865F2` 白底 4.61 达标、深底 `#313338` 只有 2.74 不达标——但 Discord 官方本来就只把它当填充底配白字（白字压上去正是 4.61）。同理 GitHub 链接蓝 `#0969DA` 白底 5.19，其官方暗档用的是另一个值 `#58a6ff`，**品牌方自己就分档**。于是判据从「看色值」变成「看用途」：一个色只能出现在它达标的底上。这与 ADR-0009 不冲突，恰好是它的推论。
   **〔001 回写，2026-09-25〕** 判据「看用途」成立，本条的**立论证据一半被换掉、一半取不到**：
   - **「逐值照抄官方」在没有版本戳时是不可执行的**——同一个 token 名在两个版本里是两个值（`#58a6ff` 是旧版，`@primer/primitives@11.10.0` 实为 `#4493f8`；底账 §1）。因此本条追加一条约束：**抄的是哪个包、哪个版本、哪个 token 名，必须写进主题块头部注释**，否则下一个人抄到 `#58a6ff` 也自称照抄官方。
   - **GitHub 侧「锁用途」清单是空表**：跑完官方配对后没有任何一个品牌色在它自己该在的角色上不达标（accent 在自己两档 canvas 上 5.19 / 6.11，过 4.5）。
   - **blurple 那组读数不作已证事实继续往下推**——`#5865F2`/`#313338` 属 Discord，本机取不到出处（见下）。本条的通用判据不依赖它，但它作为**例证**的地位从「实算」降为「未核实」。
   - **结构性发现**：GitHub 有公开的 design-token 产物（本次用的就是），**Discord 没有**——它的 `--base-*` 一层只存在于客户端包里。「Discord 官方值」这个概念无出处可解析，本条对 Discord 两档**悬空待裁决**，不进验收账本。

   **〔003 回写，2026-09-25〕** 两处：**版本戳从注释变成机检**，**"空表"这句的范围要收窄**。
   - 版本戳纪律不再只是一句注释：用到的官方 css 提交进 `docs/vendor/primer-11.10.0/`（底账 §8 的裁决 ①，三份 css 243,174 字节），
     门禁 `test/token-provenance.test.js` **三条**——T1 先验这份副本自身在册且 sha256 相符，T2 拿它逐值比对每个带标注的 hex，T3 拿 `size/radius.css` 对圆角那四行的 rem→px 换算。
     为什么要 T1：只验"CSS == 副本"的检查，若副本可被静默改写，就变成两个人对同一份谎言签字。读数 **26 个标注 hex / 26 个相等 / 0 个对不上**。
     T1 取哈希前把 CRLF 归一回 LF：本仓库 `core.autocrlf=true` 且没有 `.gitattributes`，换一份 clone 出来那三份 css 就是 CRLF，而 `PROVENANCE.json` 记的是上游 LF 文件的哈希——不归一等于把这条写成"clone 之后必红"，
     而那正是底账 §8 当初否掉"探针不进 CI"的理由。**没有顺手加 `.gitattributes`**：那是全仓库范围的共享配置改动，一次改行的规范化会把 `docs/` 与 `public/` 一起卷进这轮提交里没有的diff。
   - **T2 的判据形状在收尾时换了一次**：原来那条地板是"标注数 ≥ 8"，只挡得住"把标注全删光"——13 条里删掉 5 条它照样绿，而那 5 个值从此不再对着官方文件比一次。
     现在是**完整性**：在册块内每一条 hex 声明都必须带官方 token 标注，除 `--c-sN` 那十二个（它们是本档自己钉死的科目色，出处在 `:root` 与 `§7(a)-5c`，标一个官方名反而是造假出处）。
     判据拿 T2 已查过的那批属性名做集合差，不另写一套"这行里有没有 `/*`"的猜测——两套口径不一致时，会有一条值绕过逐值比对却在完整性上判绿（注释写在声明前面的那种形状）。
     会判红由两个变异体证明：`memory_hex.css`（值换成同名的旧版本 `#58a6ff`）、`lost_annot.css`（值分毫未动，只擦掉一行的出处注释——旧地板对这一刀是绿的）。
   - **T3 补的是这条链上最后一格"标了出处却没人查"**：`radius.css` 提交进了 `docs/vendor/`、被 T1 的哈希钉住，但没有任何一条断言读它——
     于是 `--r-md: 6px /* --borderRadius-medium (0.375rem) */` 这行要是说谎（换算写错、token 名抄错），仓库里同时躺着"官方文件"和"逐字钉死的表"，却没人把两者对一次。
     本条把 rem→px 的换算（1rem=16px，`html` 上没有 font-size 覆盖）也变成读数，四行 × 两块 = 8 行全部逐值过；判据与 T2 同形（先完整性再逐值，地板按**声明**数算而不是按标注数算，因为"把声明删光"时相对判据自己看不见自己）。
     两个变异体：`radius_drift.css`（标 medium 写 12px）、`lost_radius.css`（擦掉那一行的注释）。
   - **本条第一次出现"两个官方梯之间选一个"**。GitHub 暗档的 accent/语义色，emphasis 梯（`#1f6feb` 等）压在本档 `--bg`/`--surface` 上作文字只有 **4.08/3.74**，四族全落 4.5 以下；
     foreground 梯（`#388bfd`/`#3fb950`/`#f85149`/`#d29922`）作文字/图标 对 `--bg` 5.65~7.50、对 `--surface` 5.16~6.86，作填充底压深色字 5.65~7.50，两头都在窗内。于是本档取 foreground 梯，**没有一个 hex 是为凑数改的**（仍是照抄），
     但代价要写明：这一档的按钮蓝是 GitHub 的 outline/link 蓝，不是它的主按钮强调蓝——观感归 007 的浏览器读数由人裁一次。
   - 于是"GitHub 侧锁用途清单是空表"这句**只在亮档成立**。暗档不是"品牌色在它自己角色上不达标"（那才是空表定义的那种错），而是**本站每族只有两个槽**（一个填充底 + 一个压在其上的字），
     官方三梯（emphasis / foreground / onEmphasis）里没有任何一梯能同时填满这两个槽且都达标：onEmphasis 只有 `#ffffff`，白字配 foreground 梯是 2.52~3.35。
     结论没变（不改色值、不锁出一个假值），变的是"空表"不该被读成"两档都不用做取舍"。
   - `--ink-faint=#656c76`（官方 `--fgColor-disabled`）在本档 `--bg` 上 **3.57**。这一族**四档全不达标**（各对着本块自己的 `--bg` 实算：白板亮 `#b8b8b8` 1.98 / 白板暗 `#5a5a5a` 2.67 / GitHub 亮 `#818b98` 3.45 / GitHub 暗 3.57），所以它是 0012 之前就存在的一处待裁项、不是本档新引入的洞——本档反而把它从「白板的 1.98」抬到 3.57。〔上一轮此处写作「白板 1.58、GitHub 亮档 3.24」，两个数都复现不出来，且 3.24 是拿 `--surface` 当底算的、与并列的 3.57（拿 `--bg`）不同底，不可比；已按实算替换〕按本条"锁用途而不改色值"处理——留着，交 007 一并裁，不换成达标的假值冒充照抄。

**主题切换入口**：编辑态工具行里一个四选一分段选择器（复用 `.seg`）。这一条同时回答 ADR-0010 后果 2 预留的那个问题——**投影时不给切换入口**。宽度账：ADR-0010 记录现状整组约 540px，四选一约 300px，合计约 840px < 1366 下可用 1270px。展示态不出现主题控件，「展示态不泄漏控件」判据（`verify-47a.js` 故事 9）不变；收起顶栏后主题不可改，ADR-0010 后果 1「没有部分控件仍可用的中间态」原样成立。

> **〔0013 改口，2026-09-25〕** 上面第一句（四选一**常驻**分段选择器）已被 ADR-0013 作废：工具行只常驻一颗入口钮，选项在它自己的弹层里。本段其余三条——投影时不给入口、展示态不出现主题控件、收起顶栏后主题不可改——**继续有效**。那笔宽度账的失效方式也记在 0013：它只量了 1366 一头，同一支名单在 390px 那头是每档一颗常驻钮各占一格，`flex-wrap` 会为一整条控件多撑一行。

**取舍**：备选「只换外壳、墙面锁死白板」被否决——三套主题在墙上看不出差别，主题存在感为零。备选「每套主题一套布局语法」（GitHub 把作业行排成表格、Discord 做成左栏分组）被否决——它要 `ui.js` 渲染路径按主题分叉，工单 027 那整轮「内容完整 + 后排可视」验收全部重测，且布局差异无法用 token 判据表达，只能逐主题手测；「骨相」这个词因此被限定为 token 层外观属性集。备选「门槛优先、为达标允许改明度」被否决——那会做出颜色不对的 GitHub，用过那两家的人一眼看出。备选「不做现场切换，走 URL 参数」被否决——教室里没人改得了地址。

**后果（要记住的六条）**：

1. ADR-0008 那句「骨相不动」从此**只对默认主题成立**。四处文档要改写：`style.css:1-6` 那行头注释、`.rivet.md:17` 那句「取值一律走 `:root` / `body.dark-mode`」、`docs/specs/2026-09-19-visual-system-convergence.md` §5 的「锁死」口径、`CONTEXT.md` 的「白板风」词条。

**未验证**：真机一体机上 `backdrop-filter` 的性能与投影观感、八档 × 三态截图的像素裁决。这两项按 spec §(c) 那条既有口径留给用户。

**门禁已知旁路（006 挂账，本次不修）**：`style-invariants` 对含 `:is(...)`/`:where(...)` 的选择器**两问都不响**，而且两问的机制不同——动作色那一问是 `ACCENT_ALLOWED` 那条 `else if` **显式放过**，内容区那一问是 `contentCompounds` 只看复合选择器那一段的**开头**、`:is(` 开头匹配不上（是**看不见**，不是放过）。实测对：`.content, .subject-name { color: var(--accent) }` 让 `§7(a)-1` 判红，同一句包进 `:is(...)` 后该文件 25 条测试全绿。本 ADR 决定 5 那句"「只出现在可按的东西上」这条职责边界在每一档都成立"因此是**由写法纪律维持的**，不是由门禁维持的：新写的主题规则不许用 `:is`/`:where` 包内容区选择器。要不要把这条旁路堵上（改 `contentCompounds` 认 `:is(` 里的段）是一次独立裁决，不在主题化范围内——细节与复现步骤在 `.rivet.md` 样式段与本工单目录，不在这里重复。
