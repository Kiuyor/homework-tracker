# 编辑态只留一条工具区，科目筛选器删除

编辑态顶部原本是**三行**：顶栏第一行（品牌 + 展示/添加作业/收起）、顶栏第二行（日期导航，全宽居中）、以及顶栏之外的 `.manage-bar`（科目筛选 + 字号 + 暗色）。本轮把日期导航、字号、暗色**聚成顶栏第二行的一个居中组**，`.manage-bar` 整条消失。合并后编辑态顶部只剩两行，且这两行同属 sticky 的 `.topbar`。

**为什么现在能合**：`.manage-bar` 三个控件里被删掉的那个（科目筛选）占了 102px，剩下两个（字号 164px + 暗色 44px）撑不起一整条常驻工具区。而顶栏第二行本就是为"独占一行"设计的居中行，塞进这两个控件后整组约 540px，1366 下可用 1270px——**拥挤不是这一轮的问题**。

**取舍**：备选有"日期下沉进工具条，顶栏只留品牌+动作"（职责最纯：顶栏=导航，工具条=设置）——被否决，因为日期导航会失去 sticky 常驻，滚动后换日期要先滚回顶，而换日期是科代表最高频的动作。另有"两行保留、只在视觉上并区"（改动最小）——被否决，因为三者仍分处两个容器，"聚成一个区域"只完成了一半。

**本决策显式推翻** `docs/specs/2026-09-19-one-homework-per-subject.md` 故事 35（"科目筛选器……保留"）。该故事的保留理由是"在一科一条下它等价于跳到那一格"——这个等价关系仍然成立，但**跳到那一格的成本已经低到不值得为它常驻一个控件**：一科一条 + 固定科目表（ADR-0006）之后满墙最多 15 格，滚动即达。筛选器是拖拽/轮播时代（该 spec 之前）留下的残留动作。

**连带删除的链路**（不留半条）：`#subjectFilter` 与 `.filter-wrap`、`utils.js` 的 dom 项、`main.js` 的 change 监听、`ui.js` 的填充与过滤分支、`state.js` 的 `filterSubjectId`、`api.js` 缓存键里的第三段、`.subject-filter` 与 `.manage-divider` 的样式、以及样式不变量测试命中区清单中的那一项（七处变六处）。

**后果（三条）**：

1. **「收起顶栏」的语义被改写**。原先收起只隐藏 `.topbar`，`.manage-bar` 留在 `top:0` 可见——收起后能调字号、切暗色，却**换不了日期**，是个残半状态。合并后收起 = 整块工具区一起消失，只剩「显示顶栏」浮条。要操作就先展开，没有中间态。
2. **暗色切换从此只存在于编辑态**。它跟着 `.topbar` 走，而展示态顶栏 `display:none`。这与合并前一致（`.manage-bar` 在展示态本就隐藏），所以**不是本轮引入的退化**，但今后任何"投影时要不要切暗色"的诉求都要先回答这一条。
3. **展示态几何不变**：`.manage-bar` 在 `body.view-show` 下本就 `display:none`，顶栏第二行也已存在，往它加内容不改行高。因此 027 的降级阶梯输入未被触碰——但这条断言要由**重跑 027 八条守门**来兑现，不由推理兑现。

## 验收（2026-09-19 实施后）

**触控轴命中区**（`--blink-settings=primaryPointerType=2`，非 `setEmulatedMedia`），1920×1080 与 1366×768 两档读数一致：`#prevDate` 44×44、`#nextDate` 44×44、`#todayBtn` 58×44、`#fontSizeSlider` 90×44、`#darkmodeBtn` 44×44、`#addBtn` 156×44、`#modeToggle` 78×44、`#collapseBtn` 44×44。搬迁没有弄丢 016 挣来的任何一像素。

**排布**：`.tool-row` 在两档视口下都只占**一行**（高 44px，@y=99），子项顺序 `date-nav → font-wrap → tool-btn`；顶栏总高 **159px，与合并前逐像素相同**——后果 3 里那句"不改行高"由此兑现。

**收起语义**：点「收起顶栏」后 `.topbar` / `.tool-row` / `#dateNav` / `#fontSizeSlider` / `#darkmodeBtn` 全部隐藏，只剩 `.expand-bar` 在 y=16。后果 1 的"没有中间态"成立。

**回归**：`npm test` 82/82；027 八条守门 × 两档视口 = 20 条读数全部通过，新 33 在 192 字负载下仍走到 `fit=0.550` 兜底档——展示态阶梯未动。其中**新 35 已随本决策改写**：原断言「选中筛选器后编辑态只见那一科」换成断言它的反面（筛选器与 `.manage-bar` 不存在、编辑态一次列出 7 格、五个控件都在 `.tool-row` 内、顶栏高仍 159）。

**未验证**：真机一体机上工具行的触控手感（滑块与暗色钮现在是邻居，中间隔 24px，误按率要实测）；15 科满墙时编辑态一次列出全部科目后的滚动找科成本——这正是本决策赌的那件事，纸面推理说它可接受，没在真机上验证过。
