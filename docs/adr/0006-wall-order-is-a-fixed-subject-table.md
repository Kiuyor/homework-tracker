# 墙上科目顺序固定为主科优先表，取消作业级拖拽排序

一科一条之后，"拖一行"就等于"拖一个科目"，而 `sort_order` 的含义也随之从"科内次序"变成"科目在墙上的先后"。真实数据支持取消这个动作：8 个上课日里有 6 天的墙序完全等于当天的录入顺序，只有 2026-07-14 留有同一秒批量改动的痕迹——用过，但极少。而它带来的代价是负的：墙上顺序受科代表当天先录哪一科影响，后排无法靠位置记忆。

现决定三件事一并生效：

1. **格子常驻**：六个主科的格子永远在墙上，当天没作业的格子标「未布置」。历史 8 天里有 2 天不足六科，这是常态而非例外。
2. **顺序写死**：语文→数学→英语→物理→化学→生物。不在表上的科目（自动新建的政治、历史等）按建立先后排在表尾。`subjects.sort_order` 这个字段六科全为 0、从未被写过，本决策不启用它。
3. **删除拖拽**：`drag.js`、`.drag-handle`、`PUT /api/homeworks/reorder` 与其测试一并移除。编辑态每一行变成"点整行即改"+ 一个删除按钮，行内不再有编辑按钮。

**取舍**：备选"保留拖拽、语义改为拖科目顺序"（零删除、零迁移），被否决——它把"墙的形状取决于录入顺序"这个缺陷永久保留下来；也考虑过"启用 `subjects.sort_order` 并加一个科目管理页排一次"，被否决——为一个几乎不发生的诉求再加一套 CRUD 界面，与 ADR-0002 的减法方向相反。写死主科表与 ADR-0004"科目是开放集合"不冲突：**新科目照样能建、照样上墙**，只是排在表尾；被否决的是"硬限最多六科上墙"那一种读法。

**后果（必须记住的两条）**：
1. 「未布置」成为展示态的一等文案，与 ADR-0003 之下"整日空墙"那句专属文案要分层写清楚：格子级说"这一科没留"，整墙级说"今日作业待公布"。
2. 工单 016（触控轴命中区）的范围缩小：`.row-action-btn` 从两项变一项（只剩删除），`.drag-handle` 整项消失。顶栏那几个偏小的控件仍然要修，本票不背这个锅。
