# 展示降级恢复纵向滚动，废除轮播分页

本 ADR **推翻 ADR-0004 的「后果 2」**：那条写的是"压到极限改轮播分页，不再退回纵向滚动，因为教室后排没有人能滚动那面墙"。当时之所以需要轮播，是因为一面墙上可能有很多条作业、且每科可能多条。ADR-0005 与 ADR-0006 落地之后，这个前提没了：格子数 = 科目数，每格一条，六个主科格子固定形状。轮播分页变成一台只在异常情况下才启动的机器，而它一旦被启动，代价是"其余科目被连坐、每科停留八秒"（这正是工单 015 量出来的那个症状）。

现决定：降级阶梯保留前两档（压缩间距与行高 → 缩字号到 `FIT_FLOOR`），**第三档由轮播分页改回纵向滚动**。科目数超过六个时格子继续往下排，3 列自适应行数不变，装不下就让整面墙可上下滚。

**取舍**：备选"把整个降级阶梯一起删掉"（格子数=科目数、不压不缩），被否决——真实内容确实有长到三行的（5/60 条带换行），完全不缩字号会让后排读不到；备选"轮播只在超过六科时启用"（保留代码当保险），被否决——留着 `showPageTimer`、页码角标、`renderSignature` 与翻页的相互作用，就是留着工单 011/015 那一整类状态机缺陷的复发面。"教室里没人能滚动屏幕"这个理由仍然成立，但它的严重级下降了：滚动只在科目异常多时才成为必需，而不是每节课都遇到。

**后果（必须记住的三条）**：
1. ADR-0004 的"取消纵向滚动"那半句以本文为准；读那条 ADR 时不要照抄它的兜底方案。
2. 工单 011 的自适应行数保留，轮播、页码角标、`showPageTimer`、`paged-out` 相关样式全部移除。
3. 「屏上每一条都完整、不被静默裁切」（原故事 35）重新变成**滚动**保证的事：`.hw-list` 与墙体的 `overflow: hidden` 要换成可滚，否则缩到下限仍然会裁切——这条不属于本 ADR，是它留下的工单。
