# 主题化：四套主题 × 明暗两档，全部活在 token 层

日期：2026-09-25　依据：[ADR-0012](../adr/0012-visual-structure-is-per-theme-but-token-only.md)　承接：[ADR-0008](../adr/0008-visual-work-stays-within-whiteboard-style.md)（部分作废）、[ADR-0009](../adr/0009-accent-color-is-for-actions-only.md)（不动）、[ADR-0010](../adr/0010-edit-toolbar-merged-into-topbar.md) 后果 2（本规格回答它）

## 1. 问题陈述

`public/style.css` 现在只有一张脸：`:root`（白板风亮档，`:44-87`）与 `body.dark-mode`（同一套骨相的暗档，`:679-711`）。用户要的三套长相——GitHub、Discord、液态玻璃——都没有落点：

- 门禁 `test/style-invariants.test.js:132` 的 `TOKEN_BLOCKS` 只放行这两个块，**任何新主题块里的 hex 都会被 §7(a)-2 判成「游离硬编码色」**。这不是「颜色不好看」，是新骨相无处安放。
- `style.css:1-6` 那句「白板上只有文字。无卡片、无投影、无装饰」把 Discord 的深底面板与玻璃的半透浮层挡在门外。ADR-0008 第 7、9 行把这两件事列为已否决备选，并写明「要推翻需新 ADR 显式作废」——ADR-0012 就是那张 ADR。
- ADR-0010 后果 2 预留了一句话：「今后任何『投影时要不要切暗色』的诉求都要先回答这一条」。三套主题进来，这个问题必须回答，见本规格故事 22。

值得做的理由：ADR-0011 已把科目收成六科闭集、ADR-0010 已把顶栏收成两行，产品的功能面收干净了；剩下唯一还影响「科代表愿不愿意用」的维度就是长相。

## 2. 方案概述

**两轴正交**：主题（4）× 档位（明/暗，2）= 8 套 token。其中 2 套已存在（白板风亮/暗），新增 6 个块。

**接缝设计**（优先复用，尽量用最高的那条）：

| 接缝 | 现状 | 本次怎么用 |
| --- | --- | --- |
| `ui.js:5 subjectColor()` → `var(--c-sN)` | 返回的是 **CSS 变量名**，不是色值 | **零改动即跨档**。八档各自覆写 `--c-sN`，JS 侧一行都不用碰。这是本次改动最重要的复用点 |
| `body.dark-mode` 类开关 | `ui.js:361-364` + `main.js:213-220` | 明暗轴原样不动。新主题轴是**并列的另一条 class**，不改这条 |
| `style-invariants` 的 `blockOf(selector)` | 按选择器字符串精确取块 | 新块沿用同类命名 `body.theme-<name>` / `body.theme-<name>.dark-mode`，解析器不用改逻辑，只扩清单 |
| **主题名单**（新增） | 不存在 | 名单**只写在 CSS 里**（块的 selector 本身），`ui.js` 的按钮数组由一条一致性断言与它对齐。复制名单会破掉 ADR-0011「名单只在一处」那条纪律 |

**外观族 token 名单**（"成套完整声明"的范围，ADR-0012 决定 3 指向此处）：
`--bg --surface --ink --ink-dim --ink-faint --line --accent --accent-strong --on-accent --on-ink --success --danger --warn --c-s1..--c-s12`
\+ 圆角族**全量** `--r-sm --r-md --r-lg --r-pill --r-full`（`style.css:103-107` 实有五个，早先这行只列了三个——按这份名单写断言会漏掉 `--r-lg`/`--r-full` 两个真 token 的回落，正是要防的那件事）
\+ 材质 `--glass-blur/--glass-alpha/--floor-alpha`（本规格新建，现无）。**不含 `--sp-*` 与 `--show-*`**（跨主题唯一，见 §4 细化 1）。

**这份名单刻意不含 `--c-yu..--c-sheng` 六个别名（`:root:82-87`），而它们是个陷阱**：别名只在 `html` 上声明，`var(--c-s1)` 在 html 的 computed-value time 就定死了，
`body.theme-*` 覆写 `--c-sN` **追不动它们**——今天全站零读者（`grep` 只在 `style.css:668` 一句注释里提到旧用法），所以看不见；一旦有人写 `color: var(--c-yu)`，
它会在暗档与所有主题下都渲染成白板风亮档红。处理方式在工单 002：**删掉这六行**，不是把别名塞进八块名单（那是 48 行死声明换一个人不踩坑）。

> 〔002 已做，2026-09-25〕六行已从 `:root` 删除，原处留一行注释指回门禁 `§7(a)-7e`（反向断言：别名不得再出现定义或引用）。
> 上面那句"`grep` 只在 `style.css:668` 一句注释里提到旧用法"是**实施前坐标**，实施后全仓命中分三类，都不算"当作现役 token"：
> ① 注释里的历史叙述（`style.css:672` 那句"原来 .toast.error 借用语文红"）；② ADR-0011 后果 1——它原本把别名写成存在理由，现随 002 加了〔002 回写〕收口；
> ③ 旧 spec `2026-09-19-visual-system-convergence.md:41` 那句"**现状是** `.toast.error` 借用 `--c-yu`"——那是它自己那一轮的现在时，属于历史记录，**不改写**。

## 3. 用户故事

每条可独立验证。标 **〔实算〕** 的以 `.scratch/` 里的矩阵脚本读数为判据，不许用眼境代替。

**结构（1-6）**

1. 存在八个 token 块：`:root`、`body.dark-mode`、`body.theme-github`、`body.theme-github.dark-mode`、`body.theme-discord`、`body.theme-discord.dark-mode`、`body.theme-glass`、`body.theme-glass.dark-mode`。〔实算：矩阵脚本 `--blocks` 能逐个取到〕
2. 白板风仍是默认：`<body>` 不带任何 `theme-*` 类时，页面与本规格实施前**逐像素一致**（含亮暗两档）。判据：`--show-*`、`--sp-*` 一字未改，且 `:root`/`body.dark-mode` 两块的 FROZEN 值不变。
3. 每个新块**成套完整声明**外观族全部 token，缺一项即失败。不存在任何"靠级联回落到白板风取值"的漏项。
4. 新块内的颜色一律写成 token 定义（`--x: #hex` 形式），**不写** `border-radius: 14px` 这类裸值——§7(a)-3 的 `SPACING` 正则含 `border-radius`，且那条测试**不看** `TOKEN_BLOCKS` 豁免（`:136` 的豁免只在 §7(a)-2 里），裸 px 圆角会直接判红。
5. `--c-s7..--c-s12` 在新块里同样要有值（六科闭集下它们常规路径读不到，但故事 3 要求成套完整，且 ADR-0011 第 6 条保住了表外历史数据读 s7 的路径）。
6. 主题的 DOM 结构、网格布局、断点与 `--show-*` 承重层跨八档**完全一致**：展示态降级阶梯四档在任一主题下触发点相同。

**取色（7-12）**

7. GitHub 与 Discord 的四个档位**直接复用**现有两组锁死六色，不新算 hex。判据：这两档的 `--c-s1..s6` 取值与 `:root`（亮）或 `body.dark-mode`（暗）**逐字相同**。〔实算：对各自 `--bg` 与 `--surface` 均 ≥4:1〕
8. 玻璃档亮、暗两套**不新算六色**：六色各自逐字复用现有的两组锁死值，达标条件从"算六个新 hex"换成一条 **`--bg` 窗口**——玻璃亮档的 `--bg` 要**浅到**让既有亮档六色仍 ≥4:1，玻璃暗档的 `--bg` 只要**别浅出窗口**（窗口很宽）。〔实算：`contrast-baseline.md §3` 底表：亮档 `#f2f5f9` 最坏 4.00 过、`#eef2f7` 3.90 已败；暗档 `#171b21`→6.80 / `#1c2128`→6.37 / `#232830`→5.83 全过〕判据：任一 `body.theme-*` 块的 `--bg` 相对**该块自己那组的六色**最坏读数 ≥4:1，由门禁钉住。不许为了"更透"降低 α。
9. 玻璃档内容区落在实底上，写成 token：暗档 `--floor-alpha ≥ 0.88` **实测站得住**（真边界在 0.82~0.85 之间，0.88 有余量）。亮档那条 0.92 **不再是科目色的地板**——`--c-s4` 3.80 / `--c-s6` 3.66 在 0.92 的半透白玻璃上，α 拉到 0.95 也只有 3.92，**没有任何 α 能让科目色在半透浮层上达标**（背衬亮度未知，Class B 死锁，不靠数字解）。0.92 换个位置继续成立，且这才是它的真身：**浮层上的文字下限**（`--ink-dim` 在 0.88 只有 3.82、0.92 才到 4.20）。内容区那侧压在**已知** `--bg` 上是 Class A，判据在故事 8 的窗口里。科目色所落的底**必须**是实底，绝不能是透明层。〔实算：浮层 `--ink-dim` ≥4:1 @ α≥0.92（亮）/0.88（暗）；反向断言「科目色选择器不得挂在带 `backdrop-filter` 的层上」——现状天然成立，`--subject-color` 只由 `ui.js:78` 与 `ui.js:108` 写入，两处都是内容区〕
10. 玻璃材质（`backdrop-filter`）只出现在顶栏、弹层、浮条、toast 四类浮层选择器上；内容区、科目名、正文、截止时间所在节点一次都不出现。判据：反向断言「`--glass-*` 与 `backdrop-filter` 不得出现在 `CONTENT` 正则命中的选择器上」（复用 `:83` 那份 `CONTENT` 名单）。
11. 同一科目跨八档**保持色相族**：语文在任何档都是红族、数学蓝族、英语品红族、物理青绿族、化学橙族、生物绿族。判据（001 之后收窄）：**条件断言**——只在某一档真的引入新 hex 时才跑"新算值与原锁死值的色相角差 ≤ 阈值（先取 20°）"；本规格实施后没有任何一档重算 hex（见故事 8），漂移量恒为 0°，跑它无对象。而且这条量的轴本身偏弱：只降明度可以让 Δh 保持 0° 而把"绿"做成"黑绿"。真正的控制是故事 8 那条 `--bg` 窗口的最坏读数 ≥4:1，加 008 的后排人工裁决。
12. 品牌官方 hex 逐值照抄优先于本站 4:1 门槛；不达标处**锁用途而不改色值**。落地形式：该色只能出现在它达标的角色上（如 blurple 只能作填充底配 `--on-accent`，不得作深底上的文字色或描边色）。判据：反向断言「品牌色在 `--ink-dim`/描边角色上出现的读数 ≥ 门槛」，光"色值抄对了"不算过。

**控件（13-19）**

13. 编辑态工具行（`.tool-row`）多一个四选一主题选择器，复用 `.seg`/`.seg-opt`；整行仍是**唯一**的显示设置区，不新增第三条工具条（`.rivet.md:16` 口径）。
14. 四档标签用中文：白板 / GitHub / Discord / 玻璃。选择器有 `aria-label`，当前档 `aria-pressed`/`.active` 可读。
15. 每个主题按钮命中区 ≥44×44px，触屏档（`@media (hover: none)`）不得改小——需同时把该控件加进 `style-invariants` 的 `NEED` 名单（`:228-238`）与 §7(a)-6b 的检查范围。
16. 工具行加宽后 1366px 下不换行、不溢出：ADR-0010 记录现状约 540px，四选一约 300px，合计约 840px < 可用 1270px。判据：真机/CDP 量 `.tool-row` 的 `getBoundingClientRect()` 与 `scrollWidth > clientWidth` 为 false。
17. 选中主题态用该主题自己的 `--accent` 上色（`.seg-opt.active` 已在 `ACCENT_ALLOWED:94` 认账清单内，不需扩清单）。内容区拿不到动作色——ADR-0009 在八档全部成立。
18. 焦点环仍是全站那一条 `2px solid var(--accent)`：新控件不自带 `outline`，不出现 `outline:none`（`:175-176` 双反向断言）。
19. 主题选择只影响配色/材质/圆角/字重，**不改变字号**：绝对字号滑块与展示倍率与主题无耦合。

> **〔故事 13/16 改口，2026-09-25，ADR-0013〕** 002 落地后被要求换成**按钮入口**：工具行只常驻一颗 `#themeBtn`（文案「主题 · 当前档」，由 `ui.js` 写，HTML 里仍不出现名单），选项 `#themePop` 在它自己的弹层里、默认收起。
> - **故事 13 的"四选一常驻"作废**，"整行仍是唯一的显示设置区、不新增第三条工具条"不变——弹层挂在入口下面，随顶栏一起隐藏，不是一条新工具条。复用 `.seg`/`.seg-opt` 也不变，只是从横排改成竖排。
> - **故事 16 的判据换形**：从「`.tool-row` 整组不换行」变成「入口一颗钮不换行 ＋ 弹层不溢出视口」，而且要按**名单最长那一刻**（四档）量，不是当前长度。原来那笔账只量了 1366 一头；390px 那头每多一档就多一颗常驻钮，`flex-wrap` 会为整条控件多撑一行。实测读数（同源 iframe 逐宽度）：四档模拟下入口 116×44、弹层 116×194、单项 114×48、390px 无横向滚动、弹层右边缘 245 < 390。
> - 故事 14（`aria-label` 与当前档可读）、15（≥44 命中区）、17（动作色）、18（焦点环）、20/21/22/23/24 **一字未动**：15 靠 `.theme-seg .seg-opt` 这条选择器原样平移进弹层，14 的"当前档可读"改由入口文案承担（不打开也读得出来）。
> - 新增的门禁是 `§7(a)-7f`（入口必须是 `<button>`、带 `aria-expanded`/`aria-controls`、弹层默认 `hidden` 且 CSS 里有对应的 `display:none`）；007 的宽度读数按其新判据重开。

**偏好与状态（20-24）**

20. 选择主题后写入 `localStorage['hw_theme']`，取值 `whiteboard|github|discord|glass`；非法值按 `whiteboard` 处理。
21. 无 `hw_theme` 时落在 `whiteboard`。**主题不跟随系统**：系统没有主题信号。`prefers-color-scheme` 仍然只驱动明暗轴，`hw_darkmode` 的读写路径一字不动。
22. **展示态不给主题入口，也读不到未保存的选择**——这一条就是 ADR-0010 后果 2 那个预留问题的答案：投影时不切主题。理由与暗色钮同（顶栏在展示态 `display:none`），因此不新增泄漏面。
23. 收起顶栏后改不了主题（ADR-0010 后果 1「没有部分控件仍可用的中间态」原样成立）。

**降级与无障碍（25-28）**

25. 不支持 `backdrop-filter` 时（`@supports` 探测），玻璃退成「同一 α、无 blur」的实面浮层；**内容区读数在支持与不支持两种情况下完全一致**，因为科目色永远落在实底上（故事 9），透明层从来不带信息。
26. `prefers-reduced-motion: reduce` 下主题切换不得引入新动效（`style.css:1051` 那条媒体查询是既有归属地；本规格不新增过渡）。
27. 八档 × 展示/编辑 × 明暗 = 32 个静态形状，其中**内容区**的对比度判据全部成立：正文按 4.5:1、科目色与次级文字按项目自订的 ≥4:1（后排可辨识）、描边/分隔线按 3:1 非文本判据。**不许把 40px 的墙标题按 4.5 判**——每行标出它按哪条门槛判。
28. 切主题不改变任何数据、不触发任何写请求。

## 4. 已定决策

ADR-0012 的六条决定全文有效，此处不重述。以下是 ADR 措辞需要在实施时**收窄**的两处，以及一处 ADR 未覆盖的补充：

1. **「成套完整声明」的范围收窄为外观族**。ADR-0012 第 3 条原本写的是「自己说满全部 token」，但 `--show-*` 被 ADR-0008 第 13 行与 ADR-0012 决定 2 自己钉成"只许改名不许改值"，`--sp-*` 跨主题唯一——把它们纳入"必须重声明"会自相矛盾。**本条已回写 ADR**：决定 3 现在的正文就是「限外观族 + 逐条名单见本规格 §2」。ADR 与本规格口径一致，不留单方面解释。
2. **块命名用 class 不用 `data-theme`**。ADR 未规定。理由：`body.dark-mode` 已是 class，`style-invariants` 的 `blockOf()` 按 selector 字符串精确取块，class 命名让解析器零改动。
3. **新增：色相族锁定**（故事 11）。ADR-0012 决定 4 只说"保持色相族"，未给判据；本规格给的 20° 这个可算数沿用 spec §5 的空档判据，但 001 跑完后它的形态变了：**条件断言**，只在某档真的引入新 hex 时才跑。本方案的落地结果是一个 hex 都不重算（故事 8），Δh 恒 0，且 20° 这条量的是错的轴——实质把关交给故事 8 的 `--bg` 窗口与 008 的后排裁决。

## 5. 取值来源与实算规程（第一张票，其余票阻塞于它）

**判据工具**：`.scratch/` 下的矩阵脚本（parse-don't-retype 版）。它从 CSS 里**解析** token 值，接受 `--bg LABEL=SPEC` 多目标底、`var()` 按块解析、半透明底自动扫五档背衬并输出 `min~max`、`--selftest` 钉住 sRGB 数学与 CSS 解析器。

**规矩**：任何进入本规格的色值必须是解析结果，不能是手敲。手敲是本次审计里唯一出现过的假读数来源。

跑法（三条，按序）：

```
node .scratch/<矩阵脚本> --selftest                                   # 绿了才继续
node ... public/style.css --blocks ':root,body.dark-mode' \
  --fg '^--c-s[1-6]$' --threshold 4 \
  --bg "whiteboard=#ffffff" --bg "gh-subtle=#f6f8fa" \
  --bg "gh-canvas=#0d1117" --bg "gh-subtleD=#161b22" \
  --bg "dc-base=#313338" --bg "dc-secondary=#2b2d31" --bg "dc-deepest=#1e1f22"   # Class A：既有锁死值够不够
node ... public/style.css --fg '^--c-s[1-6]$|^--ink$' --threshold 4 \
  --bg "fog=rgba(255,255,255,0.85)" --bg "floor92=rgba(255,255,255,0.92)" --bg "floor88=rgba(20,20,20,0.88)"  # Class B：**浮层** α 下限证明（跑出来是浮层文字那侧的数，实底压在已知 --bg 上属 Class A 窗口，见故事 8/9 与底账 §3）
```

**Class 分类决定修法**（不许混）：

- **Class A｜跨档搬运**：为 X 档锁死的值落在 Y 档底上不达标 → 用 Y 档自己那套锁死值，或者**什么都不用做**。跑完再设计，最便宜的结果是一张空的重做清单。
- **Class B｜底是半透明的**：读数在五档背衬间跨过门槛（`min < T ≤ max`）→ **修法不是颜色**。要么给那层一个 α 有下限的实底，要么把材质限制在"不携带信息"的层。有人提议"换个稍深一点的 hex"时拒绝他，并把 sweep 区间当证据交出去。
- **Class C｜它本来就不是文本对**：描边、投影、焦点环、装饰雾 → 按 3:1 非文本判，或**带理由地**排除。静默排除就是把真失败报成噪音。

## 7. 测试决策

**在哪些接缝测**（从上往下，越少越好）：

1. **最高接缝＝CSS 文本本身**。`style-invariants.test.js` 已经是一台"解析源码 + 判据"的机器，八档的全部颜色/圆角/命中区约束都在这条接缝上判，不需要起浏览器。新增的"成套完整声明""玻璃材质只在浮层""科目色不得挂在带 `backdrop-filter` 的层上""`--bg` 窗口最坏读数 ≥4:1""主题块头部版本戳"几条也挂这条接缝；"色相族 ≤20°"降为**条件断言**（仅当某档引入新 hex 时才跑，见故事 11）。
2. **第二接缝＝`subjectColor()` 的返回值**。断言它跨八档返回**同一个字符串** `var(--c-sN)`——这是"JS 不参与主题"的证明，写一条就够。
3. **第三接缝＝`.tool-row` 的几何**（CDP 真量）。只有故事 16 的宽度账和故事 15 的命中区需要运行时，且**只在有设备/浏览器时**测。
4. 对比度**不进单元测试**，进 `.scratch/` 矩阵脚本 + 账本，因为它要的是外部源值与 sweep 证明，不是一次性断言。

**"完成"长什么样**：`node --test test/` 全绿（含扩表后的 §7(a) 全部）+ 矩阵脚本三条跑完 Class B 为空 + 八档 × 三态截图交给你亲自裁 + 真机上 `backdrop-filter` 性能读数。少最后一项，就**不许**在 spec 里写"已验证"。
