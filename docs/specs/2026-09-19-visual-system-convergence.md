# 视觉体系收敛：在白板风骨相内把失控的取值收进 token

日期：2026-09-19 · 分支：`fix/known-defects`
上游：本轮 grill 共识（ADR-0008、ADR-0009）· 不改任何数据语义与后端

## 1. 出发点与边界

诉求原话是"优化UI/UX"，追问后定为**整体视觉方向重做**。但重做的落点不是换长相：

- **骨相不动**。`style.css:1-6` 那句「白板上只有文字。无卡片、无投影、无装饰」经复核**继续成立**（ADR-0008）。被明确否决的三个备选：引入卡片与纵深、翻转为暗色默认、加品牌识别色。
- 本轮要修的是**体系缺失**，实测三处：`--accent` 定义后使用 **0 次**；`--space-*` 三档总共用 **6 次**而 `padding:`/`gap:` 声明有 **66 处**；焦点环一处有（`:295`）、一处被 `outline: none` 抹掉（`:532`）。

一句话：**换的是纪律，不是脸。**

## 2. 九条决策

| # | 决策 | 被否决的备选 |
|---|---|---|
| 1 | 骨相不动，白板风内做体系化 | 卡片/纵深、暗色默认、品牌色 |
| 2 | 主色＝深靶蓝 `#263cba`，**只归动作** | 语境取色、继续用墨色 |
| 3 | 范围＝全量：token 层 + 三界面 + 焦点环 + 字体链 | 只动展示态、只建 token |
| 4 | 展示态承重层**值不动，只统一命名** | 全重映射并接受重测 |
| 5 | 硬编码全吸附到阶梯，但**命中区不得因吸附缩小**，宁可上取一档；顺带清掉 016 六处欠债 | 不设下限、只命名不改值 |
| 6 | 只给**拉丁/数字**定字体身份，且只落纯数字语境 | 只纠假不引资产、打包完整中文 |
| 7 | 科目色池**锁死六主科，只重排表外 s7–s12** | 完全不动、12 色全重排 |
| 8 | 验收＝代码不变量 + 44px 实测 + 三态截图由用户亲自裁 | 只跑断言、只看截图 |
| 9 | 先提交上一轮 1442 行，本轮从空工作区起步 | 叠加、另起分支 |

## 3. token 层

### 3.1 颜色

```
--accent: #263cba   /* h231 S66 L44，白底 8.61:1 —— 实算见 §5 */
--accent-strong     /* 反相时的前景色（accent 底上的文字）*/
暗色档 --accent: #99a8ff   /* 对 #141414 为 8.25:1 */
```

**已知且刻意接受的一处靠近**：`--accent` h231 与数学蓝 s2 h215 只差 **16°**。它由 ADR-0009 的职责分离化解——动作只出现在控件、科目色只出现在内容区，两者不同屏同角色。**不为此再躲色相**，12 色池几乎占满色轮，躲无可躲。

语义色**脱离科目色池**（本轮新增，见 §6 偏差 ①）：`--danger`、`--warn`、`--success` 三个独立 token。现状是 `.toast.error` 与 `.row-action-btn.del:hover` 直接借用 `--c-yu`（语文红），等于"错误"和"语文"共用一个颜色；`.offline-dot` 借用 `--c-s5`（化学橙）。s8 重排腾出琥珀 `#b45309`，正好转作 `--warn`。

### 3.2 间距阶梯

`--sp-1..9` = **2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64**（4 的倍数，2px 一档微距留给图标级缝隙）。

吸附规则三条：① 取最近档；② 等距时**上取**；③ 任何可点击元素的命中区**只增不减**。
现有 `--space-sm/md/lg`(12/20/32) 由 `--sp-4/6/7`(12/24/32) 取代——20→24 是本轮少数几处肉眼可见的疏朗变化之一。

### 3.3 圆角

`--r-sm: 8` / `--r-md: 12` / `--r-lg: 16` / `--r-pill: 999px` / `--r-full: 50%`。
现状 30px 的胶囊在 25–48px 高的元素上都会被浏览器夹成半高，与 `999px` 渲染结果逐像素相同——所以这条收敛**零视觉变化**，只是把魔法数字清掉。输入框与 `.seg` 的 10px → `--r-md` 12px 有变化。

### 3.4 字体链

```
正文/中文：  'PingFang SC', 'Microsoft YaHei', system-ui, sans-serif   ← 删掉永远取不到的 'Noto Sans SC'
拉丁语境：   'IBM Plex Sans', <上面的链>
```

**拉丁语境**＝只含数字与拉丁字符、不含汉字的文本，全项目**四处**：`.show-clock`（`14:30`）、`#fontSizeLabel`（`44px`）、`.show-font-val`（`100%`）、`.show-font button`（`A−`/`A+`）。
中英混排串（`.date-label` 的"今天 9月19日 星期六"、`.deadline` 的"次日 18:00"）**明确排除**——它们若吃拉丁字体，一串里两种字，等于自己造出不一致。

资产：`public/fonts/ibm-plex-sans-600-latin.woff2`（24,252 B，Google Fonts 标准 `latin` 子集，非 `text=` 微子集，将来新增拉丁语境不缺字）+ `public/fonts/LICENSE-IBM-Plex-Sans.txt`（SIL OFL 1.1，允许随字体分发）。**绿色版免联网不受影响**——字体是本地文件，不是 CDN。

## 4. 承重层：本轮不许改值的地方

这是本轮最容易出事的地方，单列。上一轮的降级阶梯是**量出来的**，不是设计出来的。

| 位置 | 现状 | 处置 |
|---|---|---|
| `--show-gap-v/-gap-h/-row-pad/-head-gap/-deadline-gap/-line-h` 两档 | `body.view-show{}` + `.show-dense{}` | **值一字不动**，只纳入统一命名 |
| `body.view-show .subject-head { padding-bottom }` | `6px` | 同上——实施期收进 `--show-head-pad`，**不吸附**（它和 `-head-gap` 是同一处几何） |
| `body.view-show .main` padding | `40px 48px` | **不改值**。它决定墙的可容宽度，动它＝移动阶梯起点。收进 `--show-main-pad-v/-h` |
| `@media (min-width:1600px)` 的 `.main` padding | `56px 72px` | 同上——改为在同一条媒体查询里覆写那两个变量，值不变 |
| `--show-rows` / `--fit-scale` / `--show-scale` | JS 写入 | 不动 JS 侧逻辑 |
| 六主科色 `--c-s1..s6` | `:root` 与 `body.dark-mode` 各一组 | **锁死**，含暗色档 |

行号不写：本文档初稿里的 `:824-839` 一类坐标在本轮编辑后已全部失准，故一律改用选择器定位。

> **〔2026-09-25 主题化轮追加，ADR-0012 / 工单 002〕** 上表最后一行「六主科色 `:root` 与 `body.dark-mode` 各一组，**锁死**」——
> **口径的形状变了，取值一个字没变**。主题化之后是"**八档各自锁死**"：每套主题 × 明暗各一块，六主科色在每一块里都完整重写一份；
> 而 ADR-0012 决定 4 的实算结论是**八档全部复用现有这两组六色、一个 hex 都不重算**（工单 001 底账），所以此刻 `--c-s1..s6` 与本表写它时逐字相同。
> 判据也不在这里了：由 `test/style-invariants.test.js` 的 `§7(a)-5`（白板两组 + 展示态承重层）与 `§7(a)-5c`（主题档整块逐字钉死）把守。
> 同一轮还删掉了 `:root` 上那六行 `--c-yu..--c-sheng` 别名（本表 §41 那句"现状是 `.toast.error` 借用 `--c-yu`"到此为止是历史叙述），理由与判据见 ADR-0011 后果 1 的〔002 回写〕。

工单 027 的八条守门 × 两档视口 = 20 条读数，本轮结束时必须仍然全部通过。

## 7. 验收判据

**(a) 代码不变量**——落成可回归断言 `test/style-invariants.test.js`（读 `public/style.css` 断言，不靠人眼）：
1. `--accent` / `--accent-strong` / `--on-accent` 使用次数由 0 变正，且**只出现在控件选择器**（已认账的选择器清单写在该断言里，新增一处就要在那里显式认账）；内容选择器（`.subject-name`/`.content`/`.hw-row .deadline`/`.hw-empty`/`.empty-line`/`.subject-head`）一旦出现即失败。
2. 游离硬编码 `#fff` / `#333` / `#444` / `#141414` / `#1d7a3f` / `#2d9e52` / `#ff6b5e` 在 `:root` 与 `body.dark-mode` 两个 token 块之外归零。
3. `padding` / `margin*` / `gap` / `border-radius` / `top|right|bottom|left` 声明中不出现裸 px 字面量，除：`0`、`auto`、百分比、`calc()`、`clamp()`，以及白名单两处——§4 承重层变量各自**的定义行**（那里必须写死数字），和滑块 thumb 的 `margin-top: -6px`（它是 `(3px轨道 − 15px滑块)/2` 的算式结果，不是间距选择）。
4. 全文无 `outline: none`；焦点环由文件顶部一条 `:where(...)` :focus-visible 规则统一给（特异性压到 0，组件不必各写一份）。
5. 六主科色 `--c-s1..s6`（明/暗两组）与 `--show-*` 全部档位取值，与本轮开始时逐字相同。
6. §6 那七处命中区在 CSS 里的声明值 ≥44px（几何实测见 (b)，此条只挡"源码被改回去"）。

**(b) 44px 实测**：headless Chrome 真实 coarse/none 触控轴（`--blink-settings=primaryPointerType=2,...`，**不用** `Emulation.setEmulatedMedia`——它在本项目静默失效过），逐处量 §6 全部七项 × 两档视口。

**(c) 三态截图**：展示态 / 编辑态 / 暗色，交用户亲自裁。

**(d) 不回退**：`npm test` 全绿 + 027 八条守门重跑。

## 8. 与 grill 共识的偏差（六条，供回裁）

① **新增语义色 token**（§3.1 末）。grill 的九条里没有这一项，它来自实施期发现：`.toast.error` 与删除按钮 hover 借用 `--c-yu`，"错误"与"语文"同色。属于"把失控的收进体系"的同一主题，但确实是新增主张。

② **展示态 `.main` 的 padding 纳入承重层**（§4）。grill 第 4 条只点名了 6 个 `--show-*` 变量；实施期发现 `.main` 的 `40px 48px` 同样是阶梯起点，按同一意图一并保护。同一条理由又把 `.subject-head` 的 `padding-bottom: 6px` 收了进来（新增 `--show-head-pad`）——它和 `-head-gap` 是同一处几何，吸附它等于移动阶梯起点 2px。

③ **表外第六色由 345° 改为 297°**。grill 说的是"落在六主科之间的空档中点"，实算发现 325→5 那条缝的中点 345° 距语文仅 20°，与"拉开色相"的初衷相悖，故换缝。

④ **四句 `box-shadow` 与"无投影"骨相矛盾，本轮只登记不删除**。`.expand-bar` / `.modal` / `.toast` / `.exit-show-btn` 各有一句。ADR-0008 写的是"无投影"，但这四处的投影都在承担功能——遮罩层与背景要分离，删了会改变覆盖层可读性，而那已被上一轮量过。删除是一轮独立的判断，不该夹在体系收敛里顺手做。留待回裁。

⑤ **两处 `80px` 掉到 `64px`**（`.empty-line` 上下留白、`@media(max-width:720px)` 的 `.main` 底部留白）。间距阶梯顶到 `--sp-9: 64px` 为止，80px 出界；§3.2 的"等距上取"在界外无从执行。取 64 是"收敛到已有档位"，代价是两处留白各减 16px。若不接受，出路是把阶梯再延长一档（`--sp-10: 96px`）——那是新增主张，不擅自做。

⑥ **`.offline-badge` 的展示态放大档被合并**。原状基础档 `6px 14px`、投影档 `8px 18px`；两侧分别吸附（6→8、14→16 上取；18→16 就近）后落到同一组值，于是投影档那句 padding 覆写被删，只保留 font-size 的 clamp。也就是说：角标在投影上"更大"这件事，从此只由字号承担，不再由内边距承担。

⑦ **`server.js:14` 的启动横幅写死了库名**（本轮测量期撞见，与视觉无关）：它无条件打印 `💾 SQLite 数据库 → homework.db（项目根目录）`，而 `DB_PATH` 指到别处时照打不误。跑临时库的人会据此以为真实库被写了。数据库选择本身正确（只有 `db.js:15` 一处 `new Database(DB_PATH)`），错的只是这行日志。未改，留待回裁。

## 9. 验收结果（2026-09-19 实测）

**(a) 代码不变量**：`test/style-invariants.test.js` 12 条全绿；`npm test` 82/82（原 70 + 新 12），无回退。

**(b) 44px 实测**（真实触控轴 `--blink-settings=primaryPointerType=2,...`，`matchMedia('(hover: none)')` 在页面内自证为 true）：

**(c) 三态截图**：`.scratch/shots/vis-{edit,dark-edit,modal,show}-1920.png` + `vis-show-1366.png`。**尚未由用户裁决**，本轮不自行判定观感合格。

**(d) 不回退**：027 八条守门 × 两档视口 = 20 条读数，全部通过，其中新 33（A−/A+ 与 fit-scale 相乘）在 192 字负载下仍走到 `fit=0.550` 兜底档，说明 token 收敛没有移动阶梯。

**未验证**：真机（希沃一体机）上的字体渲染与 44px 手感；暗色档动作色的实机投影对比度；`prefers-reduced-motion` 下的新过渡。这些要教室那台设备，留给用户。

## 10. 本规格的失效处（同日，ADR-0010）

本规格验收过的 `#subjectFilter` 已在同日随科目筛选器一起删除（[ADR-0010](../adr/0010-edit-toolbar-merged-into-topbar.md)）。上表 §6 与 §9 中那两行 `#subjectFilter` 读数**作为历史记录保留**，但对应的守门断言已随之失效：

- §7(a) 第 6 条的"七处命中区"现为**六处**，`test/style-invariants.test.js` 已同步改名并删掉那一项。
- `ACCENT_ALLOWED` 认账集里的 `.subject-filter:hover` 一并删除。
- 其余六处的 CSS 值与实测读数不受影响——字号滑块与暗色按钮只是搬进了顶栏工具行，尺寸一字未改（搬迁后重测见 ADR-0010 的验收）。
